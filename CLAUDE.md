# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

PandaProd is a Godot 4.7 (Forward Plus, GDScript) desktop-pet app: a small borderless, transparent, always-on-top 256×320 window showing a pet sprite that reacts to the user's currently active application.

## Running

There is no build system, linter, or test suite. The project is run from the Godot 4.7 editor (open `project.godot`, press F5), or from the command line if a Godot binary is available (it is not on PATH by default):

```
godot --path . # run main scene (res://pet/pet.tscn)
godot --path . -e # open in editor
```

Press Esc in the running pet window to quit.

Python 3 must be on PATH (`py` or `python`): `autoload/tracker.gd` spawns `sidecar/tracker.py` as a sidecar process on startup.

The editor's game embedding (Game tab, "Embed Game on Next Play") must be **off** for F5 runs: an embedded game ignores the borderless/transparent/always-on-top settings and can't move its own window, so the pet looks like a normal non-draggable window.

## Exporting

Requires the Godot 4.7.2 export templates (Editor > Manage Export Templates). Run `./export.ps1` (PowerShell; set `$env:GODOT` to override the Godot binary path) to make a release export with the "Windows Desktop" preset in `export_presets.cfg`; `./export.ps1 -DebugBuild` makes a debug one instead. The output goes to `build/` (gitignored): `PandaProd.exe`, a copy of `sidecar/tracker.py`, which must sit directly beside the exe, `README.txt` (from `dist/README.txt`: setup and use for whoever runs the build), `PandaProd.zip` (the exe, `tracker.py` and `README.txt`: the file to share, e.g. as a GitHub Release asset; the exe is too big to commit), and in debug builds `PandaProd.console.exe` (shows Godot output in a terminal). Ship release builds: a debug build opens a console for the sidecar and prints every focused window's title. The target machine needs Python on PATH.

## Architecture

- `pet/pet.tscn` / `pet/pet.gd` — the only scene (`Pet`, a `Node2D` with a `Sprite2D` child (script `panda_sprite.gd`)) and the main scene. The whole OS window is the pet body: `pet.gd` keeps a float window position/velocity and writes `get_window().position` every `_physics_process` tick. A `Pose` state machine (`HELD`, `AIRBORNE`, `GROUNDED`, `CLING_LEFT`/`RIGHT`, announced via `pose_changed`) handles the movement. Left mouse picks the pet up by its tail: it teleports so the grip (just in from the tail, toward the butt) is under the cursor and dangles, mirrored to match the way it was facing (on a wall, toward the wall), as a damped Verlet pendulum (`_swing_step()`: the mass centre `_swing_com` keeps its momentum, falls at `SWING_GRAVITY`, decays by `SWING_DAMPING` and is held at arm's length from the tail; `sprite.rotation` points tail→mass), so moving the mouse swings it. The swing stops dead at `SWING_MAX_ANGLE` (45°) either side of hanging straight down (a free pendulum flipped and spun unnaturally). The swing doesn't fit the pet window, so it dangles in a second native window (`_held_window`, `HELD_SIZE` 448², tail at the centre, made in `_make_held_window()`: borderless, transparent, always on top, unfocusable, which also keeps it off the taskbar) whose own `PandaSprite` (`_held_sprite`) only ever shows `drag`. A window's picture reaches the screen a few frames after the window moves, so a jumping window shows its old picture in the new spot for a moment; that's why neither window resizes or changes pose as it jumps. The unused one waits at `OFFSCREEN`, already drawing what it'll need: the held window the dangle at rest, facing as a grab would (`_sync_held_sprite()` every tick); the pet window, while held, the `idle`/`sleep` frame facing the way a release would turn it (`_release_facing()`). A grab or release just swaps which window is on screen. Releasing stands it upright centred on the mass centre, pulled back inside the usable rect (`_clamp_into_bounds()`) so a release held low in a corner can't start it under the taskbar and past a wall, and throws it with the mass centre's velocity over the last `THROW_SAMPLE_TIME`. A tap (under `TAP_TIME`, moving less than `TAP_MOVE`) instead puts it back exactly where it was, so plain clicks and double-clicks don't move it. Gravity then applies, and the sprite rect collides with the usable rect (taskbar excluded) of the monitor it's on. Side edges make it cling (`CLING_LEFT`/`RIGHT`) and climb (see below), unless it's too fast to grab on: falling faster than `WALL_GRAB_MAX_FALL_SPEED` (1200 px/s), or moving faster than `WALL_GRAB_MAX_SPEED` (2200 px/s) in any direction, which is a hard throw. Then it rebounds off the wall, keeping `WALL_BOUNCE` (0.4) of its sideways speed, and falls on, turning to face away from the wall like a throw does (`THROW_FACE_MIN`). There's no ceiling: it flies over the top edge and gravity brings it back. Up there the side walls still hold it in, but it only clings once fully back in view, so it can't get stuck out of sight. Off every monitor, `_screen_bounds()` uses the nearest one, so it always falls back onto a desktop. The floor bounces or lands it, then it slides to a stop. Right-clicking opens the status window (see below), except while held: the status window would take focus and the mouse-up would miss the pet window. If the mouse-up lands on the held window anyway (the pet window lost its mouse capture), `_on_held_window_input()` releases it too (`_release()`), so the panda can never stay stuck to the cursor. On the floor (awake, slide finished) an `Activity` AI (`IDLE`/`SIT`/`WALK`/`EAT`/`GAME`/`PET`/`PROUD`) picks what to do. While `PetBrain.get_state()` is `CHUD_STATE` ("Chud"), `sprite.chud` swaps idle, sit, walk, cling and climb for their glum-faced variants (set in `_ready()` and `_on_mood_changed()`); Content and Chad use the defaults. An idle ends in a walk (`WALK_CHANCE`), a sit (`SIT_CHANCE`), a treat (`EAT_CHANCE`: eating or gaming, depending on mood) or another idle facing the other way, and every other activity returns to idle. Eating only rolls while `PetBrain.get_state()` is in `EAT_MOODS` (Content/Chad), as an incentive to be productive. Gaming (`GAME`, `_start_game()`) is its Chud mirror: it only rolls in `GAME_MOODS` (Chud) and takes the treat's share there. A mood drop into Chud mid-meal, or a rise out of it mid-game, cuts straight to idle (`_on_mood_changed`). Durations are the `IDLE_TIME`/`SIT_TIME`/`WALK_TIME` ranges, a meal is two passes of the eat animation (~12.7 s) and a gaming session nine passes of the game animation (~12 s), each ended by `PandaSprite.finished` rather than the timer. That gives roughly 30% idle, 26% walking, 22% sitting and 22% eating (Content/Chad) or gaming (Chud). Starting to eat, starting to game, being petted and the proud landing each call `Achievements.unlock()` (`bamboo`, `gamer`, `pats`, `summit`). Walks go at `WALK_SPEED`, turn away from a wall less than `MIN_WALK_ROOM` ahead, and stop on hitting a wall or monitor edge. Petting interrupts any of them, in any mood: `_update_rub()` polls the mouse every tick, and while the pet is grounded, done sliding, awake and not getting up from a fall, mouse travel over the body fills `_rub`, which drains at `RUB_DECAY`. Reaching `RUB_AMOUNT` (a brisk back-and-forth for about half a second) starts `PET`: it plays `pet` once, ends on `PandaSprite.finished`, gives `PetBrain.change_mood(PET_MOOD)` (+5) and starts `PET_COOLDOWN` (30 s, counted from the start). Any pose change (grab, landing) resets it to a short `SETTLE_TIME` idle. Held always shows the `drag` frame (in the held window), even asleep. On a wall it rests on the first climb frame for `CLING_WAIT`, then `_run_climb()` alternates `CLIMB_TIME` stretches at `CLIMB_SPEED` (`climb` anim) with `CLIMB_BREAK_TIME` breaks (`cling`), on the floor AI's `_activity_left` timer. `_snap_to_surface()` keeps it flush every tick (so a screen change or a sleep frame of another size can't leave it off its wall), and on the floor `_stay_on_floor()` lifts or drops it when the floor moves (resolution, taskbar, monitors). Up the wall, along the roof (`CLING_CEILING`, only reachable by climbing; a throw never sticks to it) away from that wall, then head-first down the far wall (`_climb_down`); `_turn_corner()` keeps the stretch going round each corner, and `_cling()` snaps flush after the frame swap. `CLIMB_DROP_HEIGHT` above the floor it hops off (`_drop(0, true)`: `_soft_drop` skips the fall frame and flop). That hop only ever ends the full route, so landing it (`_set_pose(GROUNDED)` with `_soft_drop` set) starts `PROUD`: the `proud` pose for `PROUD_TIME`, plus `PROUD_MOOD` (+10) via `PetBrain.change_mood()`; a break-fall or a grab mid-climb gets neither. Every break (not the first rest) has `CLIMB_FALL_CHANCE` of letting go instead, with `CLIMB_FALL_PUSH` sideways toward the middle of the screen, which falls and flops as usual. `_body_rect()` goes through the sprite's transform, so it's right for the turned roof frame. Airborne shows the `fall` frame: `_falling` latches on the first tick the pet is still airborne after `_collide()`, so a plain click's pick-up-and-drop (landed that same tick) never shows it. The latch holds until the pose changes, through floor bounces too. Widening to the fall frame pushes the pet off a nearby wall (keeping its speed) instead of clinging. Only impacts over `MIN_BOUNCE_SPEED` (1800 px/s) bounce; softer ones land dead. Landing with `_falling` set plays the one-shot `land` animation (`_recovering`: the AI waits, but the slide continues) and resumes the AI on `PandaSprite.finished`. Grabbing cancels it, and so does toggling sleep. Hitting a side wall mid-fall clings as usual, and `_cling()` snaps to the surface after the frame swap (a wall never holds it below the floor or above the roof). A throw faster than `THROW_FACE_MIN` (15 px/s, so even a gentle drift counts) sideways turns the panda that way. While `PetBrain.sleeping` the sleep animation overrides everything and the AI is frozen; sleep is independent of `Pose`, so a sleeping pet can still be carried, thrown and cling (climbing is frozen; waking rests first, then carries on the same way). It also quits on Esc. There's no text under the pet; mood and state are shown in the status window.
- `pet/panda_sprite.gd` — `PandaSprite` (`class_name`), the pet's `Sprite2D`. `ANIMS` maps `idle`/`sit`/`walk`/`eat`/`game`/`sleep`/`fall`/`land`/`pet`/`cling`/`climb`/`drag`/`proud` to a sheet plus per-frame `region_rect`s (the sheets have different cell widths, so no `hframes`). The regions are chosen so every frame lines up with `base_panda.png` when centred: `pandaSit.png` is [sitting, standing] in 32 px crops at x0/x38 (standing == base, so `sit` is just the sitting frame), `pandaWalk.png` is 4×34 px cells, `pandaSleep.png` is 10×63×42, `pandaEat.png` is 33×32×43 lined up with the sitting frame (its timing is baked in by repeated cells, so it plays at a flat 5.2 fps, twice per meal via `"loops": 2`), `pandaFall.png` is 5×60×34 cells (`fall` = cell 1 cropped to 33 px high since its bottom row is empty; `land` = cells 2–5), and `pandaPet.png` is 24×39×47 cells, with the body at x 0–32 lined up with `base_panda.png` and hearts in the columns to its right (timing baked in, 6 fps, `"loops": 1`). An optional `"anchor_x"` (the body's centre x in the region; `pet` uses 16) shifts the sprite, mirrored with the flip, so off-centre cells don't make the body jump. `pandaProud.png` is one base-sized frame. `pandaGamingChud.png` (`game`) is 8×60×47 cells: the panda (`pandaSitChud.png` 5 px in) at a gaming desk. It's already glum, so it has no `_chud` variant, and it plays at 6 fps with `"loops": 9`. It's drawn centred like the wide sleep frame (anchoring the body would clip the desk in the 256 px window), so the body shifts a little when it starts. Chud variants are `<name>_chud` entries, drawn instead of `<name>` while `chud` is set: `anim` stays the requested name and `_sheet` is the entry actually drawn, and flipping `chud` mid-animation swaps the sheet in place, keeping the frame and time. `pandaWalkChud.png` has the walk's 4×34 cells (cell 0 cropped to `Rect2(1,0,32,47)` doubles as `idle_chud`), `pandaSitChud.png` is the sitting frame without its 4 empty top rows (32×43, bottom-aligned), and `pandaClimbChud.png` has the climb's 6×33 cells. `play(anim)` loops an animation on `fps`, unless it has a `"sequence"` of `[frame, seconds]` steps (`land`: impact, lying with eyes shut, eyes open, two blinks, getting up). That plays once, holds the last frame and emits `finished(anim)`, and so does an fps animation with `"loops": N` after N passes (`eat`). `pandaDrag.png` is one 52×35 frame lying on its side (head right, tail far left); its `"pivot"` (the grip, 5,16) and `"mass"` (26,18) keys make `_place()` set `offset` so the node's origin is the grip and put it at the viewport centre; facing left mirrors it with a negative x `scale` (not `flip_h`, which wouldn't keep the pivot in place), and `hang_arm()` gives pet.gd the grip→mass arm, mirrored to match. Every other frame is re-centred (`_place()`, also re-run on a flip) so its bottom edge stays at `BOTTOM` (256) at `SCALE` 4, which keeps the collision floor fixed. All art faces right: `facing_right` flips it, and `surface` (`FLOOR`/`LEFT_WALL`/`RIGHT_WALL`/`CEILING`) sets rotation plus flip. `pandaClimb.png` is 6×33×48 cells drawn upright gripping a wall on the right (paws at x 32; `cling` = cell 0, `climb` = all six at 6 fps). Walls aren't rotated, just flipped toward the wall, plus `flip_v` when `climbing_down` (head-first); on the `CEILING` it's turned ±90° so the grip is up and the head leads toward `facing_right`.
- `ui/status.tscn` / `ui/status.gd` — the status window, a `Window` root that `pet.gd` instantiates on first right-click and then reuses (`open_centered(screen)`). It's a separate native OS window because `display/window/subwindows/embed_subwindows=false`; with embedding on it would be drawn inside the small pet window. It's borderless, transparent and always on top. Controls are laid out in the native 144×142 pixels of `statusDay.png` (awake) / `statusNight.png` (sleeping; the sleeping panda is baked into its field), and `content_scale_mode = canvas_items` scales them by `UI_SCALE` (5; keep it an integer so art pixels stay even), so the art stays crisp and text renders at full resolution. A `Window` has its own viewport that ignores the project's nearest-filter setting, so `status.gd` sets `canvas_item_default_texture_filter` to nearest itself (any new `Window` needs the same). `Game Font.ttf` is imported without antialiasing, hinting or subpixel positioning so the pixel text stays sharp. Regions (native px): eraser X close button (0,0,13,13), pencil drag handle (13,0,131,13), field (21,21,48,64) with a static 1:1 `base_panda.png` at (30,30,32,47) on the shadow (hidden at night), moon/sun sleep toggle `SleepButton` (14,14,15,15) calling `PetBrain.set_sleeping()`. Its textures are 15×15 frames of `buttonNight.png` (the moon, shown while awake) or `buttonDay.png` (the sun, while asleep), swapped in `_refresh()`. Frame 1 matches the art baked into the background pixel for pixel; frame 2 adds a hover ring and is used for `texture_hover`/`texture_pressed`, white box with mood state + value (21,93,96,40), "Name:" caption (71,31,53,12) above the brown name tag (71,43,53,11). The caption, `NameLabel` and `NameEdit` use font size 8 (1 font px = 1 art px for this font). A single click on the tag swaps its `NameLabel` for a `NameEdit` LineEdit (its 16 px minimum height is larger than the tag, so it grows both ways to stay centred, and `NameLabel` sits 1 px lower at (71,44,53,11) so the text lands on the same pixels in both states) (flat, zero-margin theme styles so it looks like the label). Enter or focus loss (including closing the window) commits via `PetBrain.set_pet_name()`, and Esc reverts. All text uses `ui/Game Font.ttf` through the root Control's Theme. The status controls live under `StatusPage`. The red "!" tab `ConfigTab` (96,13,14,18; `configBanner.png` frames: 1 matches the baked tab, 2 adds a gold hover ring on its sides and bottom) swaps it for `ConfigPage` (an instance of `ui/config.tscn`), whose back arrow swaps back. The "?" tab `InfoTab` (82,13,14,18) swaps in `InfoPage` (`ui/info.tscn`); `infoBanner.png` is a single hover-only frame (the tab plus a gold ring) used for `texture_hover`/`texture_pressed`, since the tab itself is baked into both status backgrounds. The green trophy tab `AchievementsTab` (110,13,14,18; `achievementBanner.png`, same two frames) swaps in `AchievementsPage` (`ui/achievements.tscn`) the same way; `_show_page()` shows one page at a time. The window always reopens on the status page. `DragHandle` and `CloseButton` stay the last children of `Root`, so they work on every page. The Root theme also styles flat `Button`s (dark slate, red on hover) and a 2 px `VScrollBar` for the config pages. The pet keeps running while it's open.
- `ui/config.tscn` / `ui/config.gd` — the config pages inside the status window (same 144×142 native layout, inheriting its theme). The menu (`config.png`) has the title "Configuration" (off-white, row y 29–41, below the back arrow (14,14,15,15)) and two 68×14 `TextureButton`s, Distractions and Productives. Their normal/hover textures are the two frames of `configButton.png` (`AtlasTexture` regions (0,0,68,14) / (68,0,68,14)). The back arrow on every config and achievements page has no normal texture, since the art is baked into the background; `arrowHover.png` (the arrow plus a gold ring) is its `texture_hover`/`texture_pressed`. Either button switches to the entries page (`config_entries.png`, `show_entries(category)`): the list's name as title; a `ScrollContainer` over the white box (23,48)–(116,99), rebuilt from `Classifier.get_keywords()` on `lists_changed`, one row per keyword with the name left and a flat "X" button at the right edge (`Classifier.remove_keyword()`); "New Entry:" and a `NewEntry` LineEdit over the white bar (21,120,79,11); and an `AddButton` over the green arrow (102,118,17,17; `greenArrow.png` frames: 1 matches the baked arrow, 2 adds a gold hover ring, used for hover/pressed). The green arrow or Enter adds (`Classifier.add_keyword()`), clears the field and scrolls to the new row. `keep_editing_on_text_submit` keeps the field live after Enter, and Esc clears it. A keyword too wide for its row is cut letter by letter (`_fit()`) and ends in ".." drawn as two 1 px dots (`_draw_dots()`): Label's `ellipsis_char` must be one character, and this font's "." has no spacing, so ".." as text runs into one bar. The entries page's back arrow returns to the menu; the menu's emits `back_to_status`.
- `autoload/achievements.gd` — autoload `Achievements`. `LIST` holds the checklist in display order (`{id, name, description}`): `summit` "Around the World" (the full climb route and proud landing), `gamer` "Touch Grass" (gaming), `bamboo` "Bamboo Brunch" (eating) and `pats` "Belly Rub" (petting). `unlock(id)` records a new one, saves `user://achievements.json` straight away and emits `unlocked(id)`; `is_unlocked(id)`. `pet.gd` calls it at the moment each thing starts on screen.
- `ui/achievements.tscn` / `ui/achievements.gd` — the achievements page inside the status window. It has the back arrow (14,14,15,15) → `back_to_status`, the title "Achievements" (off-white, row y 29–41), and a `ScrollContainer` over the white box (23,46)–(116,131), built from `Achievements.LIST`. Each entry's header row has a hand-drawn 7×7 checkbox (a green pixel tick once earned; locked names and boxes are grey), the name and a pixel caret. Clicking the header drops the description down in `Small-Font.ttf`. That font is a dot-matrix font on a 1/25-em grid, so with the window's 5× scale it's only crisp at sizes that are multiples of 5 (`DESCRIPTION_SIZE` 5; `line_spacing` 1), and it's imported without antialiasing, hinting or subpixel positioning like Game Font. Ticks follow `Achievements.unlocked` live, and `reset()` (on opening) closes every description.
- `ui/info.tscn` / `ui/info.gd` — the information page inside the status window: beginner help. `info.png` is light teal like the status page, and its white box (interior (21,31)–(117,131)) starts right under the back arrow. So the title "Information" shares the arrow's row (x 13–125, y 14–29) in the dark slate ink, and the back arrow (14,14,15,15, `arrowHover.png` on hover) emits `back_to_status`. `SECTIONS` holds `[heading, body]` pairs (Your Panda, Picking Him Up, Mood, Petting, Sleep, Config, Achievements, This Window), shown as a Game Font size-8 heading over a `Small-Font.ttf` size-5 body (`line_spacing` 1, like the achievement descriptions) in a `ScrollContainer` (23,33)–(116,130). `reset()` scrolls to the top when opened. The help text is written without numbers so it stays true whatever the mood rates are; keep it in step with the gameplay.
- `autoload/tracker.gd` — autoload singleton `Tracker` (registered under `[autoload]` in `project.godot`) exposing `active_app_changed(app: String, title: String)`, which `pet.gd` and `PetBrain` listen to. It binds UDP `127.0.0.1:47823` and, when `SPAWN_SIDECAR` is true, launches the sidecar via `OS.create_process` (`res://sidecar/tracker.py` in editor runs, `tracker.py` beside the exe in exported builds; tries `python`, then `py`; opens a console in debug builds) and kills it on exit. It tries `py -3` first (the launcher only exists with a real Python install; `python` may be the Microsoft Store placeholder, which starts and exits at once) and only counts a sidecar still running after `SPAWN_CHECK_TIME`; if none starts it shows an `OS.alert()` asking for Python 3. The port doubles as the single-instance lock: if it can't bind, another copy is running, so it alerts, sets `another_instance` (so `PetBrain` skips its exit save) and quits. Window titles are only printed in debug builds.
- `autoload/save_manager.gd` — autoload `SaveManager`. `load_json(path)` (missing/corrupt → `{}`) and `save_json(path, data)` (writes `.tmp` then renames over the target; on Windows the rename deletes the target first, so `load_json()` reads a lone `.tmp` if the target is missing). Loaders ignore values of the wrong type rather than erroring. Persisted files live in `user://` (`%APPDATA%\Godot\app_userdata\PandaProd\`, shared by editor runs and exports): `save.json` (`{"version", "mood", "name", "sleeping"}`, owned by `PetBrain`) `classification.json` (the user's custom lists, owned by `Classifier`) and `achievements.json` (`{"version", "unlocked": [ids]}`, owned by `Achievements`), kept separate so resetting one never wipes another.
- `autoload/classifier.gd` — autoload `Classifier`. Loads the `{"productive": [...], "distracting": [...]}` keyword lists from `user://classification.json` if present, else the shipped defaults in `data/classification.json`. `set_lists()` saves custom lists to `user://` and `reset_to_defaults()` deletes them; both emit `lists_changed`. The config pages edit one keyword at a time: `get_keywords(category)`, and `add_keyword(category, keyword)` (trimmed; blanks and case-insensitive duplicates rejected, returns false) / `remove_keyword()`. Both go through `set_lists()`, so every change is saved immediately. `classify(app, title)` returns `Category.PRODUCTIVE`/`DISTRACTING`/`NEUTRAL` by case-insensitive substring match (`containsn`) on process name or window title; distracting is checked first.
- `autoload/pet_brain.gd` — autoload `PetBrain`. Holds `mood` (1–100, 50 on first run), restored exactly from `user://save.json` on launch and saved on exit plus every `AUTOSAVE_INTERVAL` (30 s). Mood drifts per minute by the current category (`PRODUCTIVE_RATE`/`NEUTRAL_RATE`/`DISTRACTING_RATE`; `RATE_SCALE` speeds it up for testing). States come from the `STATES` threshold table (≤33 Chud, ≤66 Content, else Chad). `change_mood(amount)` applies one-off boosts (petting). Emits `mood_changed(mood, state)` when the integer mood or state changes. Also holds `pet_name` (default `DEFAULT_NAME` "Click Me!", max `NAME_MAX_LENGTH` 12 chars so it fits the name tag, restored from the save). `set_pet_name()` strips it, ignores blanks, emits `name_changed` and saves immediately. Holds `sleeping` (AFK mode, persisted): `set_sleeping()` emits `sleep_changed` and saves, and while asleep the mood doesn't drift at all. It reclassifies the current app on `Classifier.lists_changed`. Autoload order matters: `Tracker`, `SaveManager`, `Classifier`, `PetBrain`, then `Achievements`.
- `sidecar/tracker.py` — stdlib-only Python sidecar. Polls the Windows foreground window via ctypes/Win32 and sends one JSON datagram per change (`{"app", "title", "pid", "ts"}`), plus a 2 s heartbeat. Given `--parent-pid`, it ignores the pet's own window and exits when Godot dies. Can be run standalone for testing: `python sidecar/tracker.py`.
- Window transparency depends on several settings working together in `project.godot` (`window/size/transparent`, `window/per_pixel_transparency/allowed`, `viewport/transparent_background`, borderless, always-on-top), plus `get_viewport().transparent_bg = true` in `pet.gd`. Changing any of these can break the see-through desktop-pet effect.
- Only the sprite's rect takes clicks: `pet.gd` `_update_hit_region()` sets the pet window's `mouse_passthrough_polygon` to `_body_rect()` whenever it changes, so the transparent rest of the window (including the strip hanging over the taskbar) clicks through. The window's picture lags a few frames, so the region grows at once but shrinks only after `HIT_SHRINK_DELAY`. On Windows the region also clips drawing, so it must always cover the whole sprite.
- File logging is off (`debug/file_logging/enable_file_logging` in `project.godot`) and `Tracker` only prints window titles in debug builds: titles are private (mail subjects, documents, tabs) and must never be written to `user://logs`.
- Rendering uses the D3D12 driver on Windows and nearest-neighbor texture filtering (pixel-art friendly). The sprite fills the top 256 px of the 256×320 viewport (bottom-aligned, see `panda_sprite.gd`); the 64 px below it are empty (the text label that used to sit there was removed).

## Conventions

- `.godot/` is an editor cache (gitignored) — don't edit it. It's safe to delete; rebuild with `godot --headless --path . --import`.
- `*.import` and `*.uid` files are generated by Godot but should stay alongside their assets/scripts; `.tscn` files reference resources by `uid://`, so when renaming/moving files prefer doing it in the Godot editor. When moving by hand (editor closed), keep the `.uid`/`.import` file with its file and fix the text `path=`/`res://` references in `.tscn`, `.import` (`source_file`) and `project.godot` (`run/main_scene`, `[autoload]`).
- `project.godot` is normally edited via the editor UI; hand edits are fine but keep the existing section format.
