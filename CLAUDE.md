# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

PandaProd is a Godot 4.7 (Forward Plus, GDScript) desktop-pet app: a small borderless, transparent, always-on-top 256×320 window showing a pet sprite that reacts to the user's currently active application.

## Running

There is no build system, linter, or test suite. The project is run from the Godot 4.7 editor (open `project.godot`, press F5), or from the command line if a Godot binary is available (it is not on PATH by default):

```
godot --path . # run main scene (res://pet/pet.tscn)
godot --path . -e # open in editor
```

Press Esc in the running pet window to quit.

Python 3 must be on PATH (`python` or `py`): `autoload/tracker.gd` spawns `sidecar/tracker.py` as a sidecar process on startup.

The editor's game embedding (Game tab, "Embed Game on Next Play") must be **off** for F5 runs: an embedded game ignores the borderless/transparent/always-on-top settings and can't move its own window, so the pet looks like a normal non-draggable window.

## Exporting

Requires the Godot 4.7.2 export templates (Editor > Manage Export Templates). Run `./export.ps1` (PowerShell; set `$env:GODOT` to override the Godot binary path) to make a debug export with the "Windows Desktop" preset in `export_presets.cfg`. The output goes to `build/` (gitignored): `PandaProd.exe`, `PandaProd.console.exe` (shows Godot output in a terminal), and a copy of `sidecar/tracker.py`, which must sit directly beside the exe. The target machine needs Python on PATH.

## Layout

- Root — project config (`project.godot`, `export_presets.cfg`), `export.ps1`, and `icon.svg` (Godot default, now unused; the app icon is `art/base_panda.png`).
- `autoload/` — global singletons registered under `[autoload]`: `tracker.gd`, `save_manager.gd`, `classifier.gd`, `pet_brain.gd` now; planned `activity.gd`, `stats.gd`.
- `data/` — runtime config loaded via `res://`: `classification.json`.
- `sidecar/` — out-of-process helpers Godot launches (not Godot resources): `tracker.py`.
- `pet/` — the pet scene and its parts: `pet.tscn`, `pet.gd`, `panda_sprite.gd`; planned `panda_right.tscn`, `spring_part.gd`.
- `ui/` — UI scenes and their art/fonts: `status.tscn`/`status.gd` (+ `statusDay.png`, `statusNight.png`, `Game Font.ttf`); planned `settings.tscn`, `tasks.tscn`.
- `art/` — exported PNGs and their `.ase` sources.

## Architecture

- `pet/pet.tscn` / `pet/pet.gd` — the only scene (`Pet`, a `Node2D` with `Sprite2D` (script `panda_sprite.gd`) and `Label` children) and the main scene. The whole OS window is the pet body: `pet.gd` keeps a float window position/velocity and writes `get_window().position` every `_physics_process` tick. A `Pose` state machine (`HELD`, `AIRBORNE`, `GROUNDED`, `CLING_LEFT`/`RIGHT`, announced via `pose_changed`) handles the movement. Left mouse picks the pet up by its tail: it teleports so the grip (just in from the tail, toward the butt) is under the cursor and dangles, mirrored to match the way it was facing (on a wall, toward the wall), as a damped Verlet pendulum (`_swing_step()`: the mass centre `_swing_com` keeps its momentum, falls at `SWING_GRAVITY`, decays by `SWING_DAMPING` and is held at arm's length from the tail; `sprite.rotation` points tail→mass), so moving the mouse swings it. The swing stops dead at `SWING_MAX_ANGLE` (45°) either side of hanging straight down (a free pendulum flipped and spun unnaturally). The swing doesn't fit the pet window, so while held `_set_window_size()` grows the window (and its `content_scale_size`, keeping it 1:1) to `HELD_SIZE` (448²) with the tail at the centre, and the label is hidden. Releasing restores the window, stands it upright centred on the mass centre, and throws it with the mass centre's velocity over the last `THROW_SAMPLE_TIME`. A tap (under `TAP_TIME`, moving less than `TAP_MOVE`) instead puts it back exactly where it was, so plain clicks and double-clicks don't move it. Gravity then applies, and the sprite rect (not the label) collides with the usable rect (taskbar excluded) of the monitor it's on. Side edges make it cling (`CLING_LEFT`/`RIGHT`) and climb (see below), unless it's too fast to grab on: falling faster than `WALL_GRAB_MAX_FALL_SPEED` (1200 px/s), or moving faster than `WALL_GRAB_MAX_SPEED` (2200 px/s) in any direction, which is a hard throw. Then it rebounds off the wall, keeping `WALL_BOUNCE` (0.4) of its sideways speed, and falls on, turning to face away from the wall like a throw does (`THROW_FACE_MIN`). There's no ceiling: it flies over the top edge and gravity brings it back. Up there the side walls still hold it in, but it only clings once fully back in view, so it can't get stuck out of sight. Off every monitor, `_screen_bounds()` uses the nearest one, so it always falls back onto a desktop. The floor bounces or lands it, then it slides to a stop. Double-clicking opens the status window (see below; the pair's first click is still a normal pick-up and drop). On the floor (awake, slide finished) an `Activity` AI (`IDLE`/`SIT`/`WALK`/`EAT`/`PET`/`PROUD`) picks what to do. While `PetBrain.get_state()` is `CHUD_STATE` ("Chud"), `sprite.chud` swaps idle, sit, walk, cling and climb for their glum-faced variants (set in `_ready()` and `_on_mood_changed()`); Content and Chad use the defaults. An idle ends in a walk (`WALK_CHANCE`), a sit (`SIT_CHANCE`), an eat (`EAT_CHANCE`) or another idle facing the other way, and every other activity returns to idle. Eating only rolls while `PetBrain.get_state()` is in `EAT_MOODS` (Content/Chad), as an incentive to be productive. In Chud its chance goes to sitting instead, and a mood drop into Chud mid-meal cuts it straight to idle (`_on_mood_changed`). Durations are the `IDLE_TIME`/`SIT_TIME`/`WALK_TIME` ranges, and a meal is two passes of the eat animation (~12.7 s), ended by `PandaSprite.finished` rather than the timer. That gives roughly 30% idle, 26% walking, 22% sitting and 22% eating in Content/Chad, and 30% idle, 26% walking and 44% sitting in Chud. Walks go at `WALK_SPEED`, turn away from a wall less than `MIN_WALK_ROOM` ahead, and stop on hitting a wall or monitor edge. Petting interrupts any of them, in any mood: `_update_rub()` polls the mouse every tick, and while the pet is grounded, done sliding, awake and not getting up from a fall, mouse travel over the body fills `_rub`, which drains at `RUB_DECAY`. Reaching `RUB_AMOUNT` (a brisk back-and-forth for about half a second) starts `PET`: it plays `pet` once, ends on `PandaSprite.finished`, gives `PetBrain.change_mood(PET_MOOD)` (+5) and starts `PET_COOLDOWN` (30 s, counted from the start). Any pose change (grab, landing) resets it to a short `SETTLE_TIME` idle. Held always shows the `drag` frame, even asleep. On a wall it rests on the first climb frame for `CLING_WAIT`, then `_run_climb()` alternates `CLIMB_TIME` stretches at `CLIMB_SPEED` (`climb` anim) with `CLIMB_BREAK_TIME` breaks (`cling`), on the floor AI's `_activity_left` timer. Up the wall, along the roof (`CLING_CEILING`, only reachable by climbing; a throw never sticks to it) away from that wall, then head-first down the far wall (`_climb_down`); `_turn_corner()` keeps the stretch going round each corner, and `_cling()` snaps flush after the frame swap. `CLIMB_DROP_HEIGHT` above the floor it hops off (`_drop(0, true)`: `_soft_drop` skips the fall frame and flop). That hop only ever ends the full route, so landing it (`_set_pose(GROUNDED)` with `_soft_drop` set) starts `PROUD`: the `proud` pose for `PROUD_TIME`, plus `PROUD_MOOD` (+10) via `PetBrain.change_mood()`; a break-fall or a grab mid-climb gets neither. Every break (not the first rest) has `CLIMB_FALL_CHANCE` of letting go instead, with `CLIMB_FALL_PUSH` sideways toward the middle of the screen, which falls and flops as usual. `_body_rect()` goes through the sprite's transform, so it's right for the turned roof frame. Airborne shows the `fall` frame: `_falling` latches on the first tick the pet is still airborne after `_collide()`, so a plain click's pick-up-and-drop (landed that same tick) never shows it. The latch holds until the pose changes, through floor bounces too. Widening to the fall frame pushes the pet off a nearby wall (keeping its speed) instead of clinging. Only impacts over `MIN_BOUNCE_SPEED` (1800 px/s) bounce; softer ones land dead. Landing with `_falling` set plays the one-shot `land` animation (`_recovering`: the AI waits, but the slide continues) and resumes the AI on `PandaSprite.finished`. Grabbing cancels it, and so does toggling sleep. Hitting a side wall mid-fall clings as usual, and `_cling()` snaps to the surface after the frame swap. A throw faster than `THROW_FACE_MIN` (15 px/s, so even a gentle drift counts) sideways turns the panda that way. While `PetBrain.sleeping` the sleep animation overrides everything and the AI is frozen; sleep is independent of `Pose`, so a sleeping pet can still be carried, thrown and cling (climbing is frozen; waking rests first, then carries on the same way). It also quits on Esc and shows the mood state (or "Sleeping")/value plus the active app and its category in the label.
- `pet/panda_sprite.gd` — `PandaSprite` (`class_name`), the pet's `Sprite2D`. `ANIMS` maps `idle`/`sit`/`walk`/`eat`/`sleep`/`fall`/`land`/`pet`/`cling`/`climb`/`drag`/`proud` to a sheet plus per-frame `region_rect`s (the sheets have different cell widths, so no `hframes`). The regions are chosen so every frame lines up with `base_panda.png` when centred: `pandaSit.png` is [sitting, standing] in 32 px crops at x0/x38 (standing == base, so `sit` is just the sitting frame), `pandaWalk.png` is 4×34 px cells, `pandaSleep.png` is 10×63×42, `pandaEat.png` is 33×32×43 lined up with the sitting frame (its timing is baked in by repeated cells, so it plays at a flat 5.2 fps, twice per meal via `"loops": 2`), `pandaFall.png` is 5×60×34 cells (`fall` = cell 1 cropped to 33 px high since its bottom row is empty; `land` = cells 2–5), and `pandaPet.png` is 24×39×47 cells, with the body at x 0–32 lined up with `base_panda.png` and hearts in the columns to its right (timing baked in, 6 fps, `"loops": 1`). An optional `"anchor_x"` (the body's centre x in the region; `pet` uses 16) shifts the sprite, mirrored with the flip, so off-centre cells don't make the body jump. `pandaProud.png` is one base-sized frame. Chud variants are `<name>_chud` entries, drawn instead of `<name>` while `chud` is set: `anim` stays the requested name and `_sheet` is the entry actually drawn, and flipping `chud` mid-animation swaps the sheet in place, keeping the frame and time. `pandaWalkChud.png` has the walk's 4×34 cells (cell 0 cropped to `Rect2(1,0,32,47)` doubles as `idle_chud`), `pandaSitChud.png` is the sitting frame without its 4 empty top rows (32×43, bottom-aligned), and `pandaClimbChud.png` has the climb's 6×33 cells. `play(anim)` loops an animation on `fps`, unless it has a `"sequence"` of `[frame, seconds]` steps (`land`: impact, lying with eyes shut, eyes open, two blinks, getting up). That plays once, holds the last frame and emits `finished(anim)`, and so does an fps animation with `"loops": N` after N passes (`eat`). `pandaDrag.png` is one 52×35 frame lying on its side (head right, tail far left); its `"pivot"` (the grip, 5,16) and `"mass"` (26,18) keys make `_place()` set `offset` so the node's origin is the grip and put it at the viewport centre; facing left mirrors it with a negative x `scale` (not `flip_h`, which wouldn't keep the pivot in place), and `hang_arm()` gives pet.gd the grip→mass arm, mirrored to match. Every other frame is re-centred (`_place()`, also re-run on a flip) so its bottom edge stays at `BOTTOM` (256) at `SCALE` 4, which keeps the collision floor fixed. All art faces right: `facing_right` flips it, and `surface` (`FLOOR`/`LEFT_WALL`/`RIGHT_WALL`/`CEILING`) sets rotation plus flip. `pandaClimb.png` is 6×33×48 cells drawn upright gripping a wall on the right (paws at x 32; `cling` = cell 0, `climb` = all six at 6 fps). Walls aren't rotated, just flipped toward the wall, plus `flip_v` when `climbing_down` (head-first); on the `CEILING` it's turned ±90° so the grip is up and the head leads toward `facing_right`.
- `ui/status.tscn` / `ui/status.gd` — the status window, a `Window` root that `pet.gd` instantiates on first double-click and then reuses (`open_centered(screen)`). It's a separate native OS window because `display/window/subwindows/embed_subwindows=false`; with embedding on it would be drawn inside the small pet window. It's borderless, transparent and always on top. Controls are laid out in the native 144×142 pixels of `statusDay.png` (awake) / `statusNight.png` (sleeping; the sleeping panda is baked into its field), and `content_scale_mode = canvas_items` scales them by `UI_SCALE` (5; keep it an integer so art pixels stay even), so the art stays crisp and text renders at full resolution. A `Window` has its own viewport that ignores the project's nearest-filter setting, so `status.gd` sets `canvas_item_default_texture_filter` to nearest itself (any new `Window` needs the same). `Game Font.ttf` is imported without antialiasing, hinting or subpixel positioning so the pixel text stays sharp. Regions (native px): eraser X close button (0,0,13,13), pencil drag handle (13,0,131,13), field (21,21,48,64) with a static 1:1 `base_panda.png` at (30,30,32,47) on the shadow (hidden at night), moon/sun sleep toggle `SleepButton` (15,15,13,13) calling `PetBrain.set_sleeping()`, white box with mood state + value (21,93,96,40), "Name:" caption (71,31,53,12) above the brown name tag (71,43,53,11). The caption, `NameLabel` and `NameEdit` use font size 8 (1 font px = 1 art px for this font). A single click on the tag swaps its `NameLabel` for a `NameEdit` LineEdit (its 16 px minimum height is larger than the tag, so it grows both ways to stay centred, and `NameLabel` sits 1 px lower at (71,44,53,11) so the text lands on the same pixels in both states) (flat, zero-margin theme styles so it looks like the label). Enter or focus loss (including closing the window) commits via `PetBrain.set_pet_name()`, and Esc reverts. All text uses `ui/Game Font.ttf` through the root Control's Theme. Apart from the sleep toggle it's informational; the pet keeps running while it's open.
- `autoload/tracker.gd` — autoload singleton `Tracker` (registered under `[autoload]` in `project.godot`) exposing `active_app_changed(app: String, title: String)`, which `pet.gd` and `PetBrain` listen to. It binds UDP `127.0.0.1:47823` and, when `SPAWN_SIDECAR` is true, launches the sidecar via `OS.create_process` (`res://sidecar/tracker.py` in editor runs, `tracker.py` beside the exe in exported builds; tries `python`, then `py`; opens a console in debug builds) and kills it on exit.
- `autoload/save_manager.gd` — autoload `SaveManager`. `load_json(path)` (missing/corrupt → `{}`) and `save_json(path, data)` (writes `.tmp` then renames over the target). Persisted files live in `user://` (`%APPDATA%\Godot\app_userdata\PandaProd\`, shared by editor runs and exports): `save.json` (`{"version", "mood", "name", "sleeping"}`, owned by `PetBrain`) and `classification.json` (the user's custom lists, owned by `Classifier`), kept separate so resetting one never wipes the other.
- `autoload/classifier.gd` — autoload `Classifier`. Loads the `{"productive": [...], "distracting": [...]}` keyword lists from `user://classification.json` if present, else the shipped defaults in `data/classification.json`. `set_lists()` saves custom lists to `user://` and `reset_to_defaults()` deletes them; both emit `lists_changed` (meant for the future settings UI). `classify(app, title)` returns `Category.PRODUCTIVE`/`DISTRACTING`/`NEUTRAL` by case-insensitive substring match (`containsn`) on process name or window title; distracting is checked first.
- `autoload/pet_brain.gd` — autoload `PetBrain`. Holds `mood` (1–100, 50 on first run), restored exactly from `user://save.json` on launch and saved on exit plus every `AUTOSAVE_INTERVAL` (30 s). Mood drifts per minute by the current category (`PRODUCTIVE_RATE`/`NEUTRAL_RATE`/`DISTRACTING_RATE`; `RATE_SCALE` speeds it up for testing). States come from the `STATES` threshold table (≤33 Chud, ≤66 Content, else Chad). `change_mood(amount)` applies one-off boosts (petting). Emits `mood_changed(mood, state)` when the integer mood or state changes. Also holds `pet_name` (default `DEFAULT_NAME` "Click Me!", max `NAME_MAX_LENGTH` 12 chars so it fits the name tag, restored from the save). `set_pet_name()` strips it, ignores blanks, emits `name_changed` and saves immediately. Holds `sleeping` (AFK mode, persisted): `set_sleeping()` emits `sleep_changed` and saves, and while asleep the mood doesn't drift at all. It reclassifies the current app on `Classifier.lists_changed`. Autoload order matters: `Tracker`, `SaveManager`, `Classifier`, then `PetBrain`.
- `sidecar/tracker.py` — stdlib-only Python sidecar. Polls the Windows foreground window via ctypes/Win32 and sends one JSON datagram per change (`{"app", "title", "pid", "ts"}`), plus a 2 s heartbeat. Given `--parent-pid`, it ignores the pet's own window and exits when Godot dies. Can be run standalone for testing: `python sidecar/tracker.py`.
- Window transparency depends on several settings working together in `project.godot` (`window/size/transparent`, `window/per_pixel_transparency/allowed`, `viewport/transparent_background`, borderless, always-on-top), plus `get_viewport().transparent_bg = true` in `pet.gd`. Changing any of these can break the see-through desktop-pet effect.
- Mouse passthrough (click-through outside the sprite) is sketched but commented out in `pet.gd` `_ready()`.
- Rendering uses the D3D12 driver on Windows and nearest-neighbor texture filtering (pixel-art friendly). The sprite fills the top 256 px of the 256×320 viewport (bottom-aligned, see `panda_sprite.gd`), with the 64 px label below it.

## Conventions

- `.godot/` is an editor cache (gitignored) — don't edit it. It's safe to delete; rebuild with `godot --headless --path . --import`.
- `*.import` and `*.uid` files are generated by Godot but should stay alongside their assets/scripts; `.tscn` files reference resources by `uid://`, so when renaming/moving files prefer doing it in the Godot editor. When moving by hand (editor closed), keep the `.uid`/`.import` file with its file and fix the text `path=`/`res://` references in `.tscn`, `.import` (`source_file`) and `project.godot` (`run/main_scene`, `[autoload]`).
- `project.godot` is normally edited via the editor UI; hand edits are fine but keep the existing section format.
